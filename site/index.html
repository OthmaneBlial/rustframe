Five commands to a native app

v0.1 RC

Install once. Create anywhere. Ship when the workflow is ready.

curl --proto '=https' --tlsv1.2 -LsSf https://github.com/OthmaneBlial/rustframe/releases/download/v0.1.0-rc.1/rustframe-cli-installer.sh | sh
rustframe new my-tool --template vanilla-ts --package-manager npm --install
cd my-tool && rustframe dev
rustframe validate
rustframe build
rustframe package --verify

The CLI finds the nearest rustframe.json, owns the Vite and desktop process lifetimes together, and keeps generated native code under target/rustframe/.

Fit

RustFrame is a wedge, not a general desktop answer.

It makes the most sense when the app is still mostly frontend code, but the workflow has outgrown a browser tab.

Use RustFrame when

You want the runtime to own the desktop shell around a frontend-heavy app.

  • The app should stay mostly HTML, CSS, and JavaScript.
  • You want embedded SQLite without building the full desktop stack yourself.
  • You need scoped filesystem access, allowlisted commands, or multi-window views.
  • You want to start small and eject only if the app outgrows the hidden runner.
Do not use RustFrame when

You already know the product needs broad native depth or a larger ecosystem.

  • The app works fine as a browser tab or PWA.
  • You need mature plugin ecosystems and deeper native APIs immediately.
  • You want Chromium-level rendering consistency across every host.
  • You are already productive in Tauri or Electron and not feeling friction.

Target Workflow

One concrete job RustFrame should own: the local research desk.

research-desk is the proof point for the product story: awkward in a browser tab, but still not big enough to deserve a full native-first rewrite on day one.

01

Choose a local archive

Ask the user for a Markdown or text folder and persist the opaque grant only after explicit consent.

02

Index natively into SQLite

Walk the grant with extension and entry limits. No Python process, absolute-path API, or bundled fake workspace.

03

Watch incremental changes

Coalesce create, modify, rename, and delete events while surfacing unsupported or unreadable files honestly.

04

Review in focused windows

Keep search, tags, notes, status, and pinning synchronized through database events delivered after commit.

05

Back up, restore, and ship

Create consistent SQLite snapshots, restore behind a safety backup, export queues, and produce native installers.

Manifest snapshot

The workflow stays explicit in one contract.

{
  "schemaVersion": 1,
  "app": {
    "id": "research-desk",
    "windows": [{ "id": "main", "route": "/" }]
  },
  "security": {
    "model": "local-first",
    "permissions": [{
      "window": "main",
      "allow": ["db:read", "db:write", "fs:grants:read", "fs:grants:watch"]
    }]
  },
  "filesystem": { "roots": [], "persistGrants": true },
  "shell": { "commands": [] }
}

Manifest schema v1 is the native contract. Unknown fields, unsafe paths, undeclared permissions, weak CSPs, and stale generated database types fail validation before the app ships.

Ship

Packaging is already part of the flagship app story.

RustFrame should matter after the experiment. If the workflow becomes something people actually install, the packaging path should already be part of the default model.

Package command

Build and verify on the native host.

rustframe package --verify

The frontend builds first, then the hidden runner becomes a host-native bundle under dist/packages/ with checksums and machine-readable metadata.

Support contract

Production credibility now has an explicit boundary.

  • Native CI builds, installs, launches, and uninstalls every supported package format.
  • Platform promises and non-promises are now documented instead of implied.
  • Signing, notarization, updates, and release prep have dedicated operator guides.
  • Unsigned local output is supported and labeled explicitly in package metadata.
Current limits

Be honest about what is still early.

  • Packaging requires the matching native host toolchain; cross-host installers are not promised.
  • Signing and updates are documented, but they are still release-layer responsibilities outside the runtime.
  • Linux still has the heaviest GTK, WebKitGTK, and display-stack constraints.
